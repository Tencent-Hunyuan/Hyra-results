# Changelog

## 0.3.0 (2026-10-28)

Upgrade notes: no format or behaviour change for existing certificates. The default `greedy` search, its node
counts and coverage version 1 are unchanged; 0.1.0/0.2.0 certificates and the release bundles verify unchanged.
New: coverage certificates version 2 for the opt-in parity policies, counted by `verify` only through the
companion checker hyqec-check (2.0.0 or later).

### Certificates and verification
* `verify` consumes coverage certificates **version 2** (docs/BNB_CERT_SPEC_v2.md, revision 2.0-rc1, sha256
  408806c1...) through the companion checker hyqec-check >= 2.0.0 (`hyqec-check-v2`; tested with 2.0.0 and 2.0.1); same trust model as version 1.
  Before the checker runs, the header must match the certificate (group, instance, domain, cap, split; the v2
  identifiers; `rules` = the rule set the recorded policy writes). Afterwards the checker must exit 0 with
  `certificate_verified: true`, `status` accepted, `selection` all, and a verdict whose group, instance,
  domain, cap, rules, rules_version and `spec_revision` 2.0-rc1 equal the certificate's (docs/SOUNDNESS.md 5.2).
  The verdict's fields must have exact JSON types, and it must report `checker_version` as a version string
  >= 2.0.0. A parity-policy record now reaches the independently checked level only this way; the label records
  the rule set, the spec revision, the configured checker's name and its reported version (metadata, not
  authentication). No checker, a version-1 checker, a partial replay or a mismatching verdict never counts.
  For version 1 the verdict's group, instance, domain, cap, status and selection must match when reported.
* `--bnb-checker auto` picks `hyqec-check` / `hyqec-check-wide` for version 1 and `hyqec-check-v2` for version 2;
  explicit paths (relative ones included), checker source directories (`hyqec_check_v2/`) and command
  templates still work. Any checker problem (missing executable or command, unresolved `auto`) fails the
  coverage item (bound withheld) instead of the run; a blank `--bnb-checker` counts as none.
* `wrap-coverage` accepts version-2 files; the recorded policy is the one that writes the header's rule set.
* Evidence-params allowlists unchanged: version 2 needs no new `params` key (the policy is `params.bound`).
* Coverage certificate version 2 exporter: `--cert-version 2` (native) writes `SBCOV2` artifacts under `greedy`
  and the `greedy+s0*` policies: header identifiers `.../2`, `rules`, `rules_version` 1; ENTER records of rules
  2, 5, 6, 7 carry the packing PK; trace h_field = |PK| for these rules. `lower --bnb-cert` (and
  `run_bnb(..., emit_cert=True)`) with a parity policy writes version 2 (default 1 under greedy). Version-1 output,
  node counts and answers are unchanged for every policy; version 1 under a parity policy stays refused.

### Opt-in pruning policies
* S2 (`greedy+s0s1s2`): exact quotient membership replaces the 64-bit fingerprint test, which is kept as a
  filter. Results are identical unless a fingerprint collision occurs (none observed); no `rules_version`
  change. The default `greedy` search, its node counts and version-1 records are unchanged.

### Documentation
* docs/BNB_CERT_SPEC_v2.md (revision 2.0-rc1, byte-identical to the specification hyqec-check 2.0 implements);
  docs/SOUNDNESS.md 5.1/5.2; README: the prove -> certificate -> `verify` -> independently checked path for the
  parity policies, and where B&B is the right tool (sparse codes) and where it is slow (small dense codes),
  from an applicability study of the B&B prover (measured 2026-10-27 on 48 codes with the default search of a
  pre-release build; its tree and node counts are unchanged in this release).

### Source hygiene
* Internal references (contributor handles, internal repository names, machine paths) were removed from shipped files:
  comments in `native/bnb/s012.inc` and `s2.inc` (regenerated by `tests/native/port/gen_s012.py`, which still
  reproduces them byte for byte from the reviewed sources), tests, test fixtures' provenance and docs.
  the tests' data directory is now `tests/inputs/`; tests that used a local qldpc-challenge checkout read it from
  `HYQEC_TEST_UPSTREAM` (else they skip or fall back). The comment-only native edits change the B&B
  `source_sha256`; the preprocessed code of every rules variant (1024/4096 x w32/w64/w128) and of the default
  build is identical, and rules binaries built from both trees are byte-identical. Because checkpoints bind
  the source hash, a checkpoint written by 0.2.x does not resume under 0.3.0 (exit 6; restart the run).

## 0.2.0 (2026-10-27)

Upgrade notes: checkpoint format **v2** (`stabcert-bnb-ckpt 2`); version-1 checkpoint files are refused,
so restart interrupted runs. Native B&B builds now need **zlib** (headers and `-lz`). The new pruning
policies are opt-in; the default `greedy` search, node counts, certificates and coverage files are
unchanged, and 0.1.0 certificates and the release bundles verify unchanged.

### Checkpoints
* Native B&B checkpoints use version 2 with a CRC-32 chain over the header and every
  completion/find record, detecting accidental corruption before resume. Version-1 files
  are refused explicitly. Every completion chunk is now flushed and fsynced; write,
  flush, sync and close failures exit 1 before a successful final result. A crash leaving
  an exact prefix of the expected header restarts fresh. Tests inject I/O failures and
  process kills for header, completion, and find records. Native B&B builds now require
  zlib development headers and library (`-lz`); `doctor` and native build failures give
  installation guidance when they are missing. Pip installation/import stay compiler-free.
  Ordinary search rules are unchanged.
  Checkpoint hardening reviewed independently.

### Opt-in pruning policies
* Opt-in B&B parity rules S0, S1 (fixed) and S2: `--bound greedy+s0 | greedy+s0s1 | greedy+s0s1s2`
  (native, in a separate CPU rules build: variant suffix `-rules`, chosen automatically) and
  `lower --packing ...` (CLI). The default builds compile exactly as before. CPU only, no coverage
  certificate: their records count only through `verify --rerun-bnb` (same-prover re-execution with the
  recorded policy) and are never labelled independently checked. `verify` now prints each B&B item's
  evidence level, derived from the method and `params.bound`; unknown policies fail. The checkpoint
  header binds the policy (` bound=<policy>`; mismatch exits 6). The default `greedy` tree, node counts
  and checkpoint header are unchanged. Soundness: docs/SOUNDNESS.md section 5.1. Rules from the companion exact-distance study (S0 and S1 by
  one author, S2 by another), each reviewed independently there; integrated by the rule author and reviewed
  for this release by an independent rules reviewer and an integration reviewer. Coverage certificates remain `greedy`-only.

### Verify
* `verify`'s strict certificate parser now rejects unknown keys in an evidence item's `params` (status
  `rejected`, exit 1). The allowed keys are exactly what the writers emit (`certificate.EVIDENCE_PARAMS`):
  `bnb`: cap, domain, orbit_roots, split, stop_first, bound; `sat-drat` / `sat-drat-cubes`: encoding, bound,
  domain, xor_chunk, cardinality, orbit_roots; `witness` / `brute`: no params. Missing (legacy) keys remain
  optional, so existing certificates and the release bundles verify unchanged. A B&B coverage attachment is
  accepted only with `bound` greedy (or absent).
* `verify --bnb-checker ./relative/checker`: a relative path to a checker executable is resolved
  instead of being searched on PATH (in 0.1.0 it failed to launch, so the coverage bound was withheld;
  the 0.1.0 known issue).

## 0.1.0 (2026-10-23)

First release.

### Known issues
* `--bnb-checker` with a *relative* path to a checker executable (e.g. `./hyqec-check`) does not
  launch the checker: verify fails closed (exit 3, the coverage bound is withheld; no false bound).
  Use an absolute path, a checker source directory, a command template, or `--bnb-checker auto`.
  Fixed in 0.2.0.

### Names
* Released as **hyqec-verify** (distribution `hyqec-verify`, import `hyqec_verify`, command
  `hyqec-verify`); *stabcert* was the development name. The companion checker is **hyqec-check**
  (formerly stabcert-bnbcheck).
* File formats keep their historical `stabcert-*` ids (certificate, CNF encoding, group hash, B&B
  instance, coverage, checkpoint header) and the certificate field `stabcert_version`; existing
  certificates and bundles verify unchanged. The native engine sources are unchanged.
* Environment variables are `HYQEC_*`; the `STABCERT_*` names are deprecated aliases for 0.1.x (with a
  warning). Cache: `~/.cache/hyqec-verify`. `verify --bnb-checker auto` uses `hyqec-check` /
  `hyqec-check-wide` from PATH; a path to a checker executable or source directory (including the
  pre-rename bnbcheck) also works.

### Features
* Exact Pauli-weight distance of general (non-CSS) stabilizer codes; CSS X/Z distances for CSS input.
* Engines: random-information-set upper bounds (Python, native CPU, CUDA); branch-and-bound
  lower bounds (CPU, CUDA; the irreducible-cluster search of Dumer-Kovalev-Pryadko / Lee et al.
  App. B.2); SAT/DRAT lower bounds with a bundled drat-trim/lrat-check; brute force for small codes.
* Verified symmetry (qubit-permutation automorphisms) for B&B roots and SAT orbit roots.
* Certificates (`stabcert-certificate/1`) re-checked from scratch by `hyqec-verify verify`; B&B coverage
  certificates (`docs/BNB_CERT_SPEC.md`) checked by an independent implementation (`--bnb-checker`).
* Hard wall-clock `--budget`; checkpoint/resume bound to instance, cap, split and binary.
* Documentation: soundness argument (docs/SOUNDNESS.md), B&B coverage-certificate spec, related work
  (docs/related_work.md), a head-to-head benchmark against dist-m4ri / codeDistance (docs/benchmarks.md)
  and a B&B ablation (docs/ablation.md).

### Fixed during review (before release)
Found by the independent reviewer and the referee tests; all have negative tests in
`tests/test_certificate_adversarial.py`, `tests/test_acceptance_referee.py` and the reviewer's suite.

* **Verify-path soundness bug (SAT orbit roots):** the recorded orbit numbering was checked only as a
  partition of the qubits, not as orbits 0..m-1 each with one representative. A certificate could give
  an orbit a label with no root selector (e.g. label -1); the root constraints then excluded logicals
  the roots no longer covered (here the weight-one logicals on qubit 0), and a genuine DRAT-checked UNSAT "proved" a false bound
  (reviewer's case: S=<IZI,IIZ>, true d=1, verified as exact 2). The CNF had no empty clause; the proof was
  valid for the wrong formula. Reachable only through crafted certificate orbit data on the verify
  path; the production commands (`distance`, `lower`, cubes) build orbits only via
  `symmetry.orbits_from` / `trivial_orbits`, which always number orbits 0..m-1 with one representative
  each. An audit of the certificates and records produced during development (15 files, 14 orbit
  objects), checking exactly that numbering, found no affected orbit data. Orbit data with empty or missing
  representatives crashed (IndexError) instead. The fix: roots must cover every qubit, so the encoder
  now requires the orbit data to be a partition of all qubits into orbits 0..m-1 with exactly one valid
  representative each, and rejects anything else.
* `verify --rerun-bnb` took the lower bound from the editable `lower_bound` field; it now derives it
  (cap+1, or the re-run minimum), rebuilds the instance and compares its hash, and reuses the recorded
  packing policy.
* Witness evidence was not checked against the question's domain; recorded weights were trusted.
* The claimed result (status, d, bounds) was not compared with the verified one; mismatches now fail
  (exit 3). Integer fields (code, result, and evidence `lower_bound`/`weight`/`bound`/`xor_chunk`/`cap`/`split`)
  must be JSON integers, not equal floats or booleans; malformed or duplicate-key JSON is rejected.
* SAT cube literals were not validated (a literal 0 ended a DIMACS clause early).
* A coverage bound could count on checker exit 0 alone; an explicit `certificate_verified: true`
  report is now required.
* Truncated/malformed artifacts crashed verify; they now fail closed.
* Large artifacts were read into memory; now streamed.
* `--cross-check brute` did nothing; the budget watchdog crashed; the sdist lacked docs and tests;
  `wrap-coverage` mis-parsed the instance header; the min-mode summary showed cap+1.
* `requested_engines_proved_lower_bound` was true when the final lower bound was only the trivial
  d >= 1 (e.g. SAT timed out at W=1); it is now true only when a requested engine proved the final
  bound, with a warning otherwise (found in acceptance testing). Bounds were unaffected.
* `verify --help` said a checker was accepted on exit 0 alone if it printed no JSON; the code requires
  exit 0 and `certificate_verified: true`, and the help now says so (checker review N6).
* README quick start now verifies B&B certificates with `--rerun-bnb`, and documents that `verify`
  exits 3 when the claimed result is not reproduced by the selected checks (RC review S4).
* The legacy checkpoint format (the pre-release tool) did not bind cap or binary; hyqec-verify binds both.
