# Independent v2 checker

This package implements a separate coverage-v2 checker from the exported
specification alone. The v1 profiles remain frozen. Local brute-force checks
and v1 compatibility checks pass. The exported conformance data also pass on
this implementation: the certificate set (including medium and S2-rich certificates),
the VERIFY vectors V000-V006 and all 42,250 node vectors with every recorded
intermediate (`scripts/v2-vectors.py`). The
[public validation summary](PUBLIC_VALIDATION.md) describes the completed
release checks and their scope.

## Independence and acceptance

The implementation read only the two exported specifications, checker-owned
source and approved data exports. No prover source, implementation review or
internal S0/S1/S2 notes were used. The source specification is
the coverage-v2 specification, revision `2.0-rc1`, SHA256
`408806c15fbbfc8597fec20f4c0a0861846dc56cec027d214b984de3c59f43ee` (earlier work
targeted draft-4, `ee1687dd...`).

**rc1 change.** An S1 prune has one justification form per pruning step (9.2).
At a filter prune (9.1 step 3) the decider emits `J_S1F`: I is the wiped
variables, `K_i` their first-killer lists (one entry per value of `D_i`, in
canonical order), and ZL the recorded zero list. `VERIFY_S1F` (9.3.1) replays
J2, checks that I is distinct, that every `K_i` has exactly `|D_i|` entries,
each a killer of its own value, and that every entry of ZL is a Z-generator,
then accepts iff `Q_J` is empty. Enumeration prunes keep `J_S1E` and
`VERIFY_S1E` (9.3.2). The exported VERIFY vectors V000-V006 and the per-node
vectors are run by `scripts/v2-vectors.py`.

`native/checker_v2.cpp` copies the existing independent wide checker's streaming
parser, state transitions, traversal and task accounting into a separate
translation unit. The v1 sources are untouched. The new rule implementation
is divided into:

- `native/v2_decide.hpp`: pure canonical packing, UNIT, PROP, S0/S1/S2 decisions and
  locally generated justification data.
- `native/v2_types.hpp`: data structures for proofs, actions and derivation steps.
- `native/v2_verify.hpp`: checks using only the instance (rows and their column transpose), node labels and proof data.
  It does not call the decider, read its cached parity state or reuse its
  reduced syndrome basis.

Every attempted packing/S0/S1/S2 prune passes through `v2decide::checked`, which
calls `v2verify::verify` before returning the terminal decision. This applies
to top nodes, full task transcripts and normal task replay. A rejected
justification rejects the certificate. The exact canonical packing is
additionally compared with the record hint at every recorded prune. Path
reconstruction for a task recomputes only the branch generator at each
ancestor: every ancestor is a top-tree BRANCH entry whose full decision was
checked in the top walk.

### Recorded nodes: the walk trusts nothing until the pool result matches

In the top tree and in FULL transcripts the reading thread consumes each ENTER
record as a *claim* (rule, PK or branch generator) and continues the walk on it.
The trusted base is unchanged and still runs inline on that thread:
- the dead test, the entry fingerprint, weight and active count;
- LEAF iff `A` is empty and WEIGHT iff `w + 1 > cap`;
- the claimed rule must be permitted by the rule set, a claimed generator or
  packing entry must be an index `< m`, and a packing has at most 96 entries;
- the child enumeration, dead-suffix cuts, frontier cuts and all count and
  trace bookkeeping.

The node's full decision (`decide()`, including every VERIFY) runs as an
OpenMP task on an exact copy of the entry state and must reproduce the claim
(rule, PK, generator). The checker prints a verdict only after the parallel
region has ended, i.e. after every such task has finished. Any failure rejects.
The failure reported is the earliest in stream order, so verdict and message do
not depend on the thread count. After any failure the reading thread stops at
its next event.

Resources stay bounded for arbitrary claims:
- at most `min(16 x threads, 240)` checks are pending, each holding one state
  copy (O(n + m) bytes);
- because WEIGHT is checked inline, a claimed branch never descends past `cap`,
  so recursion depth stays at most `cap + 1`.

Test tools for this part (results in `docs/V2_PERFORMANCE.md`):
- `scripts/v2-claim-fuzz.py` rewrites single ENTER records (rule bytes, rule
  swaps re-encoded so the stream stays parseable, PK entries, generators in and
  out of range), deep in the top tree and inside FULL transcripts. It runs
  every mutant at several thread counts and under the sanitizer build.
- `scripts/v2-far-ahead.py` swaps two PK entries of one claim early in a large
  top tree. It reports how far reading got before the pooled check stopped it.
- `scripts/v2-thread-determinism.py` checks that every exported certificate has
  the same verdict, counts, trace and message at each thread count.

S2 decisions use exact binary quotient membership. Its verifier separately
checks 64 linear functionals against every domain difference, enumerates
fingerprint matches, and checks an exact separating functional for each
collision exception. A test build can deliberately set all fingerprints to
zero, exercising exceptions for every candidate action set.

The fixed S2 functional seed is `0xd1b54a32d192ed03`. Each nonpivot generator
index `g` receives the 64-bit key `mix(g + seed)`; pivot keys are determined
by the reduced equations. This was already the seed before draft-3. It affects
the justification and collision workload, not the exact decision or trace.

The separate verifier protects pruning only. The trusted base also includes
parsing and hashes, permutation/orbit validation and roots, node state and
deadness, LEAF and its logical test, WEIGHT, branch selection and enumeration,
domain restrictions and dead-suffix cuts, frontier/task replay, and count/trace
bookkeeping. Those components do not acquire a separate proof check merely
because the pruning rules have one.

Full acceptance means all canonical tasks were replayed, every prune verified,
no nontrivial logical encountered, all counts/traces/footer fields matched,
and both logical and transport EOF validated. Sample/range modes always remain
partial, including when their selected set happens to cover every task.

## Profiles and transport

The distribution version is 2.0.0. `hyqec-check-v2` reports the v2 profile.
Existing `hyqec-check` and `hyqec-check-wide` commands and modules continue to
report their frozen 1.3.0 profile. V1 inputs given to the v2 entry point delegate
to the frozen wide profile and retain its verdict version and transport behavior.
Unknown v1 header fields, including `rules` and `rules_version`, are ignored.
They never select a v2 rule or appear as rule metadata in the v1 verdict.

V2 gzip transport is bounded and streamed through the existing pipe adapter.
It requires one member and rejects additional members, padding, trailing bytes, bad CRC and truncation.
The header, decoded proof size and permutation-work limits are configurable
as for v1. No decompressed proof file is created.

The native v2 executable accepts only the private validated model produced by
the Python adapter. Use the Python CLI for untrusted inputs.

**Threads and timing fields.** With `--threads T` and T > 1 the native checker
runs T replay workers *plus* the reading thread: T + 1 native threads (and the
Python transport thread). The reading thread mostly sleeps while its backlog is
full, but CPU allocations should allow for it; the verdict's `threads` field
reports T. Because recorded-node decisions are deferred, the phase timings are
not the baseline's disjoint top/replay measurements:
- `top_wall_seconds` is the time until the reader has consumed TOP_END; checks
  of top-tree nodes may still be running then;
- `replay_wall_seconds` is the remaining wall time (`wall_seconds -
  top_wall_seconds`). It can include those outstanding top-tree checks, and
  task work that overlapped earlier parsing is not in it.

Compare whole-check `wall_seconds`, or user instruction counts, across
versions.

`tests/v2_factory.py` uses native decisions and an independent Python tree walk.
It checks coverage, transport, trace composition and transcript handling; it
is not an independent oracle for the exact v2 decider. The string-based
completion oracle and externally supplied conformance vectors have different
roles. Both the local checks and external conformance checks have passed.
Large-code throughput is characterized on a single shared CCD in
`docs/V2_PERFORMANCE.md`; multi-CCD scaling is still unmeasured.

## Draft-3/4 update from 172fa67

Draft-3 was read in full. Draft-4 resolves the two questions raised during
that read. The complete runtime behavior changes relative to `172fa67` are:

1. Derivation replay treats an empty alive set as determined with parity
   contribution zero. Valid END_ODD and ELIM steps can therefore use an empty
   set belonging to another variable. Each END still must prove its condition,
   and each ELIM still must remove a value. Previously replay rejected these
   derivations unless it encountered END_WIPED first.
2. Modified UNIT records omit values at the excluded qubit instead of recording
   `-2` placeholders. Surviving values retain canonical order, with an explicit
   mapping to the original domain for derivation generation. This changes
   internal records, not the refutation flag.
3. When modified UNIT finds both a zero generator and an empty domain, its
   generated justification now uses END_ODD for the zero generator. Previously
   it preferred END_WIPED. Both justify the same prune under draft-3/4; J is
   nonunique and is not serialized in the certificate.
4. CLI version text and v2 verdicts report `2.0-draft-4` instead of draft-2.
   The package version remains 2.0.0.

The new test-driver modes expose UNIT records and run the published VERIFY
examples. The source distribution includes their header. Naming the existing
S2 seed and documenting the trusted base make no runtime change.

Already-conforming behavior required no implementation changes: exact S1
anchor/KILL list lengths and canonical association, complete recorded UNIT
scans, truncation of zero/need records only, truncate-then-order packing,
deterministic comparators, limit comparisons and S1 filter-before-limit order.
Draft-4's v1 reader clarification matches the frozen implementation. Its
support-deletion proof changes the coverage explanation, not the algorithm.

The historical draft-4 validation after these changes established:

- Full suite: 62 tests passed, including all 48 v1 tests and 14 v2 tests.
- Both GCC UBSan and Clang ASan+UBSan passed all 14 v2 tests. The latter used
  the node driver with forced-zero S2 fingerprints. The wrong-J certificate
  test passed with the deliberately faulty native build.
- Published VERIFY examples: four valid checks accepted, ten invalid checks
  rejected, including shortened/overlong killer lists and invalid END steps.
- Modified-domain ordering, complete UNIT scans, 96-entry recording limits,
  both S1 outcomes at 32 variables, v1 unknown-field handling, and identical
  v1/v2-greedy record bytes across 18 configurations are covered.
- The 24,000-node brute-force experiment found zero unsound prunes, with the
  same rule counts as the previous milestone. A separate comparison against
  `172fa67` found zero differences in decisions and exposed unmodified
  UNIT/packing intermediates on all 24,000 nodes. This establishes regression
  agreement on that corpus, not independent external conformance.
- All 30 frozen v1 source/binary hashes were checked again and are unchanged.
  The previous 172 fixture acceptances and three partial production replays
  remain historical evidence on those identical v1 implementations.

## Specification questions reported

1. Draft-2 confirms mandatory single-member/trailer/EOF checks for v2 only.
   Ancillary gzip header fields such as mtime and filename need not be checked;
   the reader accepts them. V1 transport remains unchanged.
2. Section 5.2 says each rule uses the first `np` packing entries, but section
   6.1 can return `np > r+1` with only `r+1` entries. Rule 2 uses the explicit
   `r+1` size required by sections 6.2, 6.3 and 12. The inconsistent sentence
   was reported and corrected in draft-2.
3. Draft-3's statement that v1 has no rule fields was ambiguous about readers.
   Draft-4 confirms that this constrains canonical writers; frozen readers
   ignore unknown fields and consumers must not label v1 evidence from them.
4. Draft-3's coverage proof omitted the support-deletion step needed when a
   partial restriction is a stabilizer. Draft-4 supplies that argument.

These specification questions were resolved before the release conformance
checks summarized in [PUBLIC_VALIDATION.md](PUBLIC_VALIDATION.md).

## Run current node and VERIFY vectors

From an unpacked source export, without Git metadata:

```sh
make -j2
make build/v2-node-driver
PYTHONPATH=tests:. python3 scripts/v2-vectors.py VECTORS_DIR build/v2-node-driver
```

`VECTORS_DIR` is a separately supplied conformance dataset, not part of the
package. It contains the compressed code and node JSONL files and the rc1
VERIFY JSONL file. The strict runner checks every canonical node field and
explicit VERIFY verdict, requires one answer per input and a successful driver
exit, and exits nonzero on a mismatch. It does not replay complete searches.
Historical draft-4 adapters have a different API and no supported build target
in this release. See [PUBLIC_VALIDATION.md](PUBLIC_VALIDATION.md) for the
complete-search evidence and its scope.
