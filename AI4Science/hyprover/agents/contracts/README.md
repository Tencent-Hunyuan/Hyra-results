# Research roles and session instructions

The main agent keeps the original problem in view, compares proof routes, and assigns work. Workers develop and submit proofs. A verifier checks each argument in an independent session. The verification service uses the review report and the current notebook to publish facts and apply review decisions. The background controller starts subsequent main-agent sessions and initiates a full review of completion candidates. [Architecture](../../docs/ARCHITECTURE.md)

## Instructions loaded by each session

| Session | Instruction file | How it is loaded |
| --- | --- | --- |
| Interactive main agent | [Repository-root `AGENTS.md`](../../AGENTS.md) | Codex reads it when you run `./bin/codex` from the repository root |
| Background main agent | [`main_agent.md`](main_agent.md) | The controller links the project's `main/AGENTS.md` to this file and passes the current task and response protocol |
| Worker | [`worker.md`](worker.md) | Project creation links each worker's `AGENTS.md` to this file by default. Workers also read their own `TASK.md` each round |
| Verifier | [`verifier.md`](verifier.md) | The launcher creates the link if the verification work directory has no `AGENTS.md`. The service supplies the argument, evidence, and output path for each review |

The instruction files and the per-round prompts generated by the code are in English. Problem statements and assignments default to English and can follow the operator's language preference. [Operator preferences](../../OPERATOR.md) · [Operations guide](../../docs/operating-guide.md)

## Handing off work through the notebook

Each role reads the project's `KNOWLEDGE.md` to follow research progress. The main agent maintains the overall assessment and formal proof routes. Workers read relevant reports and verification feedback each round and keep rough work in their own workspaces. Useful intermediate claims can be recorded as conjectures, and complete proofs can be submitted directly.

Workers submit the full statement, proof, and predecessors with `fact_submit`. A single receipt containing `accepted=true`, `published=true`, and a valid `fact_id` confirms publication. Check that the fact is still active before citing it. Open full proofs and long notes as needed, and revisit arguments that depend on a withdrawn fact.

To raise a specific concern about a published fact, the main agent or a worker can use `fact_review` with the current revision and supporting evidence. The service commissions a fresh independent review. A receipt containing `accepted=true` and `applied=true` confirms the change. Projects default to text-based reasoning. The operator can enable computational checks in project settings. [Research concepts](../../docs/concepts.md) · [CLI and MCP tools](../../docs/cli-and-tools.md)
